# 音乐与影视喜欢次数统计设计

## 范围与依据

本方案已经用户确认，关联[统计分析需求](../backlog/2026-10-23-like-count-analytics.md)和[战略目标 goal-3](../project-overview/strategic-goals.md#goal-3个人收藏可准确回顾与分析)。用户随后授权按本方案实现和验证，本次授权完成交付收尾、提交与推送。

音乐与影视使用相同的分析结构，分别读取各自收藏数据的 `count`，不混合排名。正文沿用项目中文规划约定；本文是图表选型、布局与统计口径的维护入口，需求文档保留结果层面的验收标准。

## 入口与布局

音乐页在收藏概览与筛选区之间常驻显示「喜欢次数统计」卡片，打开页面即可查看。影视页通过收藏概览中的「统计分析」按钮展开，统计区默认收起。

```text
页面标题
收藏概览                     统计分析（仅影视）
喜欢次数统计卡片（音乐，包含次数分布和最喜欢的作品）
筛选与排序
喜欢次数统计（影视，展开时显示）
收藏列表
```

音乐卡片常驻显示「次数分布」和「最喜欢的作品」。两者在桌面端并排，在移动端上下排列。次数筛选状态及清除按钮紧跟分布图。

音乐排行每行显示一首歌。歌名与表演者左对齐，喜欢次数右对齐，长名称可换行。桌面端的分布标题和排行标题齐平，使用留白分隔两栏。影视统计区在桌面端并排呈现两图，在移动端上下呈现，并提供可展开的数据表。

## 图表

### 次数分布

音乐按喜欢次数逐行展示，横条长度表示该次数的歌曲占有效记录的比例。影视使用纵向柱状图，横轴为离散的喜欢次数，纵轴为条目数。

每个次数项显示喜欢次数、条目数和占当前有效记录的比例。有效记录的 `count` 为非负整数。次数缺失或无效时，页面显示异常条目数，分布图与排行只统计有效记录。

### 高喜欢次数条目

音乐按喜欢次数从高到低列出作品、表演者和喜欢次数。影视使用横向条形图，条长表示喜欢次数。

- 只纳入 `count >= 2` 的作品。
- 音乐排行最多显示 3 首。第 3 首遇到同次数作品时，按收藏列表的默认顺序取用。可以在收藏列表中按喜欢次数排序浏览其余作品。
- 影视排行展示前 10 项，第 10 项有并列时全部显示。相同次数视为并列。
- 点击作品名称可定位到收藏列表中的对应条目。
- 没有符合阈值的作品时，不强行生成排名。全部为 1 次时显示“所有作品均记录为 1 次，暂无次数差异”。

## 影视分析指标

设当前统计范围为 S，有效条目集合为 V，多次喜欢条目集合为 M，其中 M 为 V 中 `count >= 2` 的条目。每条记录计为一个条目，不按艺人、导演或主演重复展开。

| 指标 | 口径 |
| --- | --- |
| 累计喜欢次数 | V 中 `count` 的总和 |
| 多次喜欢条目 | M 的条目数，以及 M 的条目数除以 V 的条目数 |
| 多次喜欢贡献占比 | M 的 `count` 总和除以 V 的 `count` 总和 |

指标区仅展示上述三项，避免重复现有收藏概览。占比必须明确分母；分母为 0 时显示“—”，不得产生无穷或非数值结果。

## 筛选与联动

- 当前页面原有筛选条件共同确定 S，界面明确当前统计范围。
- 原有筛选改变后重新计算；排序只改变列表顺序，不改变统计结果。
- 点击分布图中的次数项后，临时将列表限定为对应次数。再次点击同一项可取消。统计基准仍为 S。
- 原有筛选条件改变时清除次数选中状态，按新的 S 计算。
- 影视页收起统计区域时清除临时次数条件，恢复原有筛选范围，避免列表保留不可见的筛选条件。
- 点击作品定位时，应确保对应条目可见：若次数临时条件将其隐藏，先取消临时条件；不改变原有筛选范围。

## 状态与可访问性

- 原有筛选结果为空时显示空状态，不生成误导性的图表。
- 喜欢次数全部相同时不生成差异化分析结论。
- 分布和排行都提供可直接读取的数值。影视页另提供可展开的数据表。
- 影视展开入口、柱选择、作品定位与影视数据表入口支持键盘操作，并暴露适用的展开或选中状态。
- 长作品名可换行，移动端不得截断关键名称或与次数标签重叠。

## 数据快照与核对示例

以下为方案确认时对仓库数据的核对快照，不是固定展示值；实际实现须从数据重新计算。

| 项目 | 音乐 | 影视 |
| --- | --- | --- |
| 收藏条目数 | 97 | 26 |
| 累计喜欢次数 | 122 | 26 |
| 喜欢次数至少 2 次的条目数 | 16 | 0 |
| 最高喜欢次数 | 5 | 1 |

音乐 1 至 5 次对应条目数分别为 81、10、4、1、1。多次喜欢条目占比为 16/97，约 16.5%；贡献占比为 41/122，约 33.6%。影视全部为 1 次，应呈现分布与无次数差异状态，而不是任意列出前十名。

数据来源：[`_data/music.yml`](../../_data/music.yml)、[`_data/movies.yml`](../../_data/movies.yml)。页面现状依据：[`_pages/music.md`](../../_pages/music.md)、[`_pages/movies.md`](../../_pages/movies.md)。

## 不包含的分析

- 不将喜欢次数等同于播放次数、观看次数、独立用户数或大众评分。
- 不推断喜欢发生的时间趋势，发行或上映日期不能作为喜欢日期。
- 首版不做艺人、曲风或导演贡献排名，避免合作署名的重复归属和收藏数量引发的误读。
- 不生成缺少数据支持的偏好结论，不新增喜欢事件采集或历史记录机制。

## 实现与验证

使用原生 HTML、CSS 与 JavaScript 渲染条形图，无额外图表运行依赖。统计模型位于 [`assets/js/like-count.js`](../../assets/js/like-count.js)，页面控制器位于 [`assets/js/collection-analytics.js`](../../assets/js/collection-analytics.js)，通过现有筛选完成后的事件获取统计基准。脚本只在音乐和影视页加载，不改变书籍和诗文页的行为。

自动化检查入口：

- `make test`：5 组统计模型测试，覆盖严格次数解析、两类占比分母、并列截断、空集合、零分母、非法次数及不变的统计基准。
- `TEST_URL=http://127.0.0.1:4173 make test-browser`：6 组 Playwright 浏览器测试，覆盖真实页面数据、筛选与排序、柱选择及清除、作品定位、收起时恢复列表、键盘操作、音乐表演者、影视数据表、异常数据、无 JavaScript 降级与响应式排版。运行环境需能解析 Playwright 并提供 Chromium；外部包路径可通过 `NODE_PATH` 指定，详见 [README](../../README.md)。
- `ruby script/validate_content.rb` 与 `bundle exec jekyll build`：内容校验及站点构建。

浏览器页面验证覆盖 1440、390、320 像素宽视口，检查图表非空、页面无横向溢出、窄屏指标不挤行及影视数据表展开状态，并人工复查截图。截图默认位于 `/tmp/like-count-analytics`，不作为站点资源发布。验证使用 Chromium 桌面与移动视口，不代表已进行实体手机或其他浏览器测试。
