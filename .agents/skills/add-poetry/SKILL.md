# Add Poetry

Add one or more works to the personal site's poetry collection using verified text and metadata. Keep changes to collection data and any necessary period, author name, or author lifespan entries unless the user requests other changes.

## Workflow

1. Confirm the repository and branch with `git status --short --branch`; preserve unrelated work. Read `docs/CONTENT_RULES.md`'s 诗文收藏 section, `_data/literature.yml`, `_data/literature_periods.yml`, `_data/person_names.yml`, `_data/literature_lifespans.yml`, `_pages/poetry.md`, and the literature rules in `script/validate_content.rb`. The current repository is authoritative for the schema and rendering.
2. Identify the work, author, version and requested extent. Check existing titles, aliases, authors and text to avoid duplicates. An existing work has no `count` field: do not increment a count or add a duplicate. If the user requests a different version or an update, distinguish it from the existing entry and clarify any consequential ambiguity.
3. Verify the original text, attribution, title, period and any translation against reliable sources, preferably an authoritative edition, library or primary source. Preserve the chosen edition's wording and punctuation rather than combining variants. Record uncertain or disputed attribution accurately; do not assert an unverified quotation is authentic. If essential text or attribution cannot be resolved, explain the gap and ask for the needed details instead of inventing them.
4. Add a YAML list item following the current schema: `id`, `title`, `author`, `period`, `region`, `type`, `form`, `language`, `aliases`, `content`, `translated_content`, `note`, `source_label`, and `source_url`. Use a unique, stable URL-safe `id`: it forms the page anchor, so do not change existing IDs casually. Use empty strings or arrays where appropriate, following existing entries. Retain data-file order within each period.
5. Use a stable author key from `_data/person_names.yml`; add a verified entry if needed. Use Chinese original names for Chinese authors and romanized names for foreign authors, with display names in the dictionary. Use `佚名` when the author cannot be confirmed. Use a `period` from the period catalog, without “代” or “时期”; put geography or polity in `region`. When a new period is necessary, verify and add its name, display range, integer start year and source URL to the catalog. Its date range describes the period, not the work's exact composition date.
6. Check the author's lifespan separately from the work's period. For a named author, look up the same `author` key in `_data/literature_lifespans.yml` and reuse a sourced entry when it is supported. If the record is missing or its dates are unsupported, use available web search to find and open a reliable biographical source, such as a library, museum, or scholarly reference. When the evidence supports both years, record integer `birth` and `death`, a display `label` following the existing entries, and `source_label` and `source_url`. Qualify approximate dates in the label and document material disagreement in `note`. If both years cannot be supported, leave `birth`, `death`, and `label` unset, use a sourced note-only entry when it explains the uncertainty, and report the gap. Skip this step for `佚名`.
7. Store original-language text in `content`, with one array item per verse line or prose paragraph according to `form` (`verse` or `prose`). Use a lowercase ISO 639 language code. For non-Chinese works, include an existing reliable Chinese translation when available, preserving its verse or paragraph form; otherwise use `translated_content: []`. Never invent a translation. For Chinese originals, use an empty translation array. Identify the translation and translator in `note` or source information when included, and verify both texts and their rights before publishing them. Use only text that can be reproduced with appropriate permission or public-domain status; if the requested text or translation cannot be reproduced, explain the limitation and seek an authorized alternative.
8. Use `source_label` and `source_url` for a stable source supporting the entry; report additional sources for attribution, period or translation when needed. Keep `note` factual and useful, including relevant version or attribution uncertainty, without presenting speculation as fact.
9. Run `make validate test-poetry` from the repository root. The poetry target builds the site before running its checks. Use the Ruby version in `.ruby-version` and the setup in `README.md`. Find each changed work by its ID in `_site/poetry/index.html` and verify the expected work period and author byline. When years are supported, confirm the byline includes the lifespan and the work details link to its source. When years are unverified or the author is anonymous, confirm the byline omits the lifespan. Follow any additional repository verification instructions and report checks that could not run.
10. Report changed files, validation results, sources and unresolved assumptions. Do not commit or push without authorization.
